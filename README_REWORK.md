# Biogas Digital Twin — เวอร์ชัน Rework (Prototype B)

ไฟล์นี้อธิบายว่ารื้อ/แก้อะไรไปบ้าง เทียบกับเวอร์ชันเดิมที่อัปโหลดมา (`AECMultiplayerTest-main`)
เพื่อให้ใช้ประกอบการตัดสินใจว่าจะใช้เวอร์ชันไหนส่งงานวิจัย หรือจะผสมสองเวอร์ชันเข้าด้วยกันก็ได้

---

## 1. สาเหตุที่ระบบเดิม "ค้าง/ติดขัด" — สิ่งที่แก้เป็นอันดับแรก

โค้ดเดิมใน `app.js` (2,402 บรรทัด) ถูกต่อเติมด้วยการ **"monkey-patch" ทับฟังก์ชันเดิมซ้ำหลายชั้น**
ตัวอย่างที่เจอในไฟล์เดิม:

- `renderer.render` ถูก reassign ทับ **3 รอบ** (multiplayer sync → proximity tag → PPE/deselect) โดยแต่ละรอบเรียกฟังก์ชันเดิมที่ห่ออยู่ข้างในต่อกันเป็นลูกโซ่
- `buildColliders` ถูก reassign ทับ **2 รอบ**
- `highlightAndShowWorkflow`, `resolveDatabaseKey`, `createEngineerAvatar`, `animateEngineerWalk` ถูก override ทับของเดิมทั้งหมด

**ผลกระทบ:** ฟังก์ชันเหล่านี้ถูกเรียกจาก `animate()` → `renderer.render()` ทุกเฟรม (60 ครั้ง/วินาที)
ถ้าโค้ดที่ถูกห่อไว้ชั้นในสุด (เช่น proximity tag หรือ PPE check) throw error แม้แต่จุดเดียว —
เช่น mesh หา child ไม่เจอ, canvas context ว่าง, หรือ object ถูกลบไปแล้วแต่ยังมีการอ้างอิงค้าง —
**การ render ทั้งเฟรมจะพังทันที** เพราะไม่มี try/catch คั่นระหว่างแต่ละชั้น คอนโซลจะเต็มไปด้วย error
ซ้ำๆ ทุกเฟรม และผู้ใช้จะเห็นเป็นอาการ "จอค้าง/ตัวละครขยับไม่ได้/ป้ายไม่ขึ้น" โดยไม่มีข้อความ error ที่ชัดเจน

### วิธีแก้ในเวอร์ชันนี้
ทุกฟังก์ชันถูกเขียนใหม่ให้ **ประกาศครั้งเดียว** ไม่มีการ override ซ้อนกันอีก และ `animate()` loop
เรียกแต่ละระบบย่อยผ่าน `safeCall(fn, label)` ที่ดัก error ไว้ — ถ้าระบบใดพัง จะเห็น error
เฉพาะจุดใน console (พร้อม label บอกว่าใครพัง) แต่เฟรมอื่นๆ ที่เหลือยังทำงานต่อได้ปกติ ไม่ค้างทั้งระบบ

## 2. สรุปตาม Requirement ที่ให้มา

| # | Requirement | สถานะเดิม | ทำอะไรในเวอร์ชันนี้ |
|---|---|---|---|
| 1 | ปรับ Scale + Lock | มีอยู่บ้างแต่ **ล็อกเฉพาะเครื่องตัวเอง** ไม่ sync ให้คนอื่นเห็น | ย้าย Lock ไปอยู่ที่ **server** เป็นสถานะกลาง sync ทุกคนเห็นตรงกัน + ผูกกับสิทธิ์ Admin |
| 2 | ปรับ X/Y/Z + หมุน + Lock | ปรับได้แต่ **ไม่ broadcast ให้ผู้เล่นอื่นเห็นเลย** (ช่องโหว่ใหญ่สำหรับแอป multiplayer) | ทุกการปรับตำแหน่ง/ขนาด/หมุน **sync เรียลไทม์ผ่าน Socket.IO** ให้ทุกคนเห็นตรงกันทันที |
| 3 | Avatar สัดส่วนคน | มีเวอร์ชัน realistic อยู่แล้ว (ดี) | คงพฤติกรรมเดิมไว้ (กล่องประกอบสัดส่วนจริง ~1.75m) ตามที่ระบุว่ายังไม่ต้องทำให้โดดเด่น รอโมเดลจริงมาใส่ทีหลัง |
| 4 | ชี้/เดินชน → ขึ้นข้อมูล | มีแค่ "เดินชน" กับคลิกจาก **รายการชิ้นส่วนด้านข้าง** เท่านั้น — **ไม่มีการคลิกที่วัตถุใน 3D โดยตรง** | เพิ่มระบบ **Raycast คลิก/แตะที่ตัวโมเดลใน 3D ได้โดยตรง** แยกจากการลากกล้อง (เช็คระยะขยับ pointer) |
| 5 | วงกลม PPE 15 เมตร | มีอยู่แล้ว แต่ผูกกับ **list ชื่อ key ตายตัว** (`['tank','manhole','pvrv','flare']`) | เปลี่ยนเป็น flag `requiresPPE` ในฐานข้อมูลแต่ละจุด — จุดที่ Admin กำหนดประเภทเองใหม่ก็ได้วงเตือนอัตโนมัติโดยไม่ต้องแก้โค้ด |
| 6 | เดินเลย/ชี้ซ้ำ → ข้อมูลหาย | มีอยู่แต่เขียนแบบ "ดัก double-click ภายใน 1.5 วินาที" ซึ่งเปราะบางและไม่ครอบคลุมการคลิกจาก 3D โดยตรง (เพราะ raycast ยังไม่มี) | รวมเป็น `selectPart()` เดียว: เลือกซ้ำจุดเดิม = ปิดป้ายทันที (toggle) ไม่ต้องจับเวลา, และเดินออกไปไกลกว่า 6 เมตรก็ปิดป้ายเหมือนเดิม |

**ไม่ได้ทำ:** ระบบ "จับ/ลาก" ชิ้นส่วนแต่ละชิ้น — ตามที่ระบุว่าจะทำให้ระบบซับซ้อนเกินไป
ใช้การชี้ (คลิก/แตะ) และเดินชนแทนทั้งหมด

## 3. ฟีเจอร์ใหม่: ระบบ Admin / Lock (ตอบโจทย์ "user แก้ไม่ได้ ปรับได้แค่ admin")

- ผู้เล่นทุกคนเข้ามาเป็น **Viewer** โดย default — แถบเลื่อนปรับตำแหน่ง/ขนาด/หมุนถูก **disabled ไว้เสมอ**
  (มองเห็นค่าปัจจุบันได้ แต่ลากไม่ได้)
- ต้องกรอกรหัสผ่าน Admin (ในแท็บ "🛠️ ปรับตำแหน่ง") เพื่อยืนยันตัวตนกับ server ก่อน ถึงจะมีสิทธิ์ปรับ
- แม้เป็น Admin แล้ว ก็ยังต้องกด **"ปลดล็อก"** อีกขั้นหนึ่งก่อนจะแก้ไขได้ (กันมือลั่นตอนโชว์งาน)
  และเมื่อจัดตำแหน่งเสร็จ กด **"ล็อกโมเดล"** อีกครั้งเพื่อป้องกันการแก้ไขโดยไม่ตั้งใจ
- สถานะ Lock/Unlock **sync ให้ทุกคนเห็นเป็น badge เดียวกัน** (🔒 / 🔓) และจำนวน Admin ที่ออนไลน์อยู่
  แสดงในแผง Multiplayer (👑 Admin: N)
- รหัสผ่าน Admin ตั้งค่าได้ผ่าน environment variable `ADMIN_PASSWORD` ตอน deploy จริงบน Railway
  (ค่า default สำหรับทดสอบคือ `biogas-admin` — **ควรเปลี่ยนก่อนใช้งานจริง**)

> ⚠️ หมายเหตุ: ระบบนี้เป็น auth ระดับ "ต้นแบบงานวิจัย" (รหัสผ่านเดียวใช้ร่วมกัน ไม่มีระบบบัญชีผู้ใช้แยกราย
> บุคคล) เหมาะสำหรับสาธิต/เก็บข้อมูลผู้ใช้งานในงานวิจัย ไม่ใช่ระดับ production security เต็มรูปแบบ

## 4. โครงสร้างไฟล์ที่เปลี่ยน

```
server.js         → เพิ่ม: admin auth, lock state, model_transform sync, broadcast แบบรวมศูนย์
public/app.js      → เขียนใหม่ทั้งหมด (จัดหมวด 15 ส่วน อ่านง่ายกว่าเดิมมาก), ไม่มี monkey-patch
public/index.html → เพิ่ม UI ล็อกอิน Admin + badge lock/unlock ในแท็บ "ปรับตำแหน่ง"
                     + badge จำนวน Admin ในแผง Multiplayer
                     + disable slider ทั้ง 5 ตัวเป็นค่าเริ่มต้น
public/styles.css → เพิ่ม style เล็กน้อยสำหรับ slider ที่ถูก disable
```

ไฟล์อื่นทั้งหมด (Dashboard.html, Equipment.html, Login.html, Digitaltwin.html ฯลฯ, logo, background)
**ไม่ได้แตะ** — ใช้ไฟล์เดิมทุกอย่าง ดังนั้นหน้าอื่นๆ ในระบบยังทำงานเหมือนเดิมทุกประการ

โครงสร้าง Backend (Railway/Node.js), Storage (Supabase), Deploy (Vercel) **ใช้ config เดิมทั้งหมด**
ไม่ต้องตั้งค่าอะไรใหม่ ยกเว้นถ้าต้องการเปลี่ยนรหัสผ่าน Admin ให้ตั้ง environment variable
`ADMIN_PASSWORD` บน Railway

## 5. วิธีทดสอบเทียบสองเวอร์ชัน

1. Deploy โฟลเดอร์นี้ไปอีกหนึ่ง service บน Railway (หรือรันคู่ขนานบนเครื่อง local คนละ port)
   แล้วเปิดเทียบกับเวอร์ชันเดิมที่ deploy ไว้แล้ว
2. ทดสอบเปิดสองแท็บ/สองเครื่อง (จำลอง multiplayer) — ลองล็อกอิน Admin ในแท็บหนึ่ง
   ปรับตำแหน่งโมเดล แล้วดูว่าอีกแท็บเห็นการเปลี่ยนแปลง real-time หรือไม่ (เวอร์ชันเดิมจะ **ไม่เห็น**
   เพราะไม่เคย sync ตรงนี้เลย)
3. ลองคลิกที่ตัวโมเดลใน 3D โดยตรง (ไม่ใช่คลิกจากลิสต์) — เวอร์ชันเดิมจะไม่ตอบสนอง เวอร์ชันนี้จะขึ้นป้าย
   ความปลอดภัยทันที และคลิกซ้ำจุดเดิมป้ายจะหายทันที (ไม่ต้องรอ 1.5 วินาทีเหมือนเดิม)
4. ปล่อยแอปทิ้งไว้นาน ๆ พร้อมเปิด browser console (F12) ดูว่ามี error สะสมรัวๆ ทุกเฟรมเหมือนเวอร์ชันเดิม
   หรือไม่ (ถ้ามี error ในเวอร์ชันนี้จะขึ้นเป็นข้อความเดี่ยวๆ พร้อมชื่อระบบที่พัง ไม่ทำให้ระบบอื่นค้างตาม)

- ฐานข้อมูลความปลอดภัย 12 จุดตามคู่มือ (สี แดง/ส้ม/ฟ้า/เขียว) — ข้อความและเนื้อหาเหมือนเดิมทุกตัวอักษร
- ระบบกำหนดประเภทอุปกรณ์เอง (Type Selector), แก้ไขข้อมูลสด (Live Edit), บันทึก/โหลดฉากเป็น .zip
- ระบบมือถือ (joystick, ปุ่ม Interact/Jump), ปุ่มลัดคีย์บอร์ด (H/T/M/U/F/R/Space)
- การเชื่อมต่อ Supabase Storage สำหรับอัปโหลดโมเดล — ใช้ credential เดิมทุกตัว
